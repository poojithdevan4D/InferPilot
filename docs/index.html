The trap, side by side

These two servers report almost identical GPU utilization. One will get ~40% more throughput from fp8 KV cache; the other gets nothing. Utilization can't separate them — the recompute-from-preemption signal can.

GPU util99%
KV-BOUND · PREEMPTING

fp8 KV helps

KV cache is full, the scheduler is preempting and recomputing tokens — wasted work fp8 can relieve.

GPU util100%
COMPUTE-BOUND · NO PREEMPTION

fp8 does nothing

The GPU math is the limit. No recompute waste to remove, so a precision change is a placebo. Save the effort.

Measured, not hypothetical

A paired study on Qwen2.5-3B (A10G, vLLM 0.29.0) using an exact recomputed-token counter added to vLLM. In the preempting regime, fp8 drove recomputed tokens to zero and throughput up. Total GPU cost: $0.81.

Honest caveat: on a 7B model the throughput win held (+33%) but recompute did not go to zero — the mechanism is model-size dependent, and InferPilot reports that instead of overclaiming. The quality preflight also detected distribution shift, so fp8 KV isn't called "lossless."
